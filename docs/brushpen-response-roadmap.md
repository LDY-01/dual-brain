# 한글 붓펜 응답 로봇: 목표와 단계별 개발 계획

작성 기준: 2026-10-07, Asia/Seoul.

개발 브랜치: `codex/korean-brushpen-response`.

이 문서는 사용자와 합의한 목표, 현재 구현 상태, 다음 작업 순서를 기록한다.
실행 방법과 좌표 데이터 형식은 [소프트웨어 개발 안내](robot-writing.md)를 참고한다.
착수·완료 날짜와 결과·증거는 [진행 기록 README](writing/README.md)에 누적한다.

## 마일스톤 한눈에 보기

**진행 원칙: 큰 글자 반복 필기 -> 고정 문장 10회 검증 -> AI 답변 -> 음성 질문.**
지금은 로봇 없이 필기 계획, 시뮬레이션, 실행 관리 기반을 준비한다. 실제 글씨가
읽히는지 확인하기 전에는 AI 답변과 음성을 실제 필기에 연결하지 않는다.

| 단계 | 마일스톤 | 상태 | 통과 결과 |
| --- | --- | --- | --- |
| M0 | 오프라인 한글 경로와 미리보기 | 구현 완료 / 사람 검수 남음 | 대표 글자와 문장이 읽히는 미리보기 |
| M1 | 펜 끝 기준 로봇 시뮬레이션 | 미시작 | 안전한 관절 경로와 도달 가능 영역 |
| M2 | 고정 텍스트 실행 관리와 기록 | 미시작 | 중지·실패 처리 및 시험 기록 |
| M3 | 실물 연결·장착·보정 | 장비 연결 대기 | 검증된 펜 끝·종이 좌표와 안전 조건 |
| M4 | 공중 이동과 접촉·선 시험 | M3 이후 | 안전한 이동, 반복 가능한 잉크 선 |
| M5 | 큰 글자 `가`, `한`, `글` 반복 시험 | M4 이후 | 글자별 가독성·획 오류·시간 기록 |
| **M6** | **같은 고정 문장 10회 시험** | **M5 이후 / 핵심 통과 관문** | **정답을 모르는 사람의 판독 결과** |
| M7 | 텍스트 질문에 대한 AI 답변 필기 | M6 통과 전 보류 | 질문에 맞는 한 문장을 실제 필기 |
| M8 | Windows 음성 인식 연결 | M7 이후 | 발화가 검증된 답변 작업으로 연결 |
| M9 | 음성 질문부터 한 문장 필기까지 평가 | M8 이후 | 전체 성공률·실패 원인·완료 시간 |
| M10 | 여러 문장 확장 | M9 통과 전 보류 | 문장 수와 종이 공간을 확장 |

**지금 할 일:** M0의 사람 검수, 이후 M1과 M2 구현.
**장비 연결 후 첫 목표:** M3~M6. M6 실패 시 M3~M5를 개선하고 같은 조건으로 재시험한다.
AI 모델 변경이나 음성 기능 추가로 물리적 필기 실패를 해결하려 하지 않는다.

완료 상태는 구현과 검증을 분리한다. 아래 반복 횟수와 성공 기준은 초기 개발용
기준이며 현재 성과나 보장된 성공률이 아니다. 기준을 바꾸면 이유와 변경 내용을
시험 전에 기록하고, 서로 다른 조건의 결과를 한 묶음으로 합치지 않는다.

## 1. 우리가 만들려는 시스템

**사용자가 말을 하면, 시스템이 그 말을 인식하고 질문에 대한 답변을 만든 뒤,
SO-101이 붓펜으로 종이에 한글 한 문장을 써서 대답한다.**

사용자의 말을 그대로 받아쓰는 기능과 구분한다. 질문을 이해하고 그에 맞는 답변을
생성해야 한다. 고정 문장은 필기 제어 시험에 사용하고, 최종 대화 기능에는 실제
답변 모델을 연결한다.

첫 버전은 한 번에 한 질문을 처리하고 답변 한 문장을 쓴다. 한 문장이 반드시
종이의 한 줄에 들어가야 하는 것은 아니다. 글자 수와 줄 수는 필기 가능 면적과
가독성을 기준으로 정한다. 처음 제안했던 5~15자는 확정 제한이 아니다.

한 문장 응답이 성공하면 여러 문장으로 확장한다. 음성 출력은 현재 필수 목표가
아니며, 로봇이 종이에 쓰는 것이 핵심 응답 방식이다.

## 2. 확정한 개발 방향

- 당장은 로봇을 연결할 수 없으므로 소프트웨어부터 개발한다.
- 실물 장비 연결과 보정은 나중에 처음부터 다시 확인한다.
- 사람이 붓펜을 장착하고 종이를 고정하는 구성으로 첫 버전을 만든다.
- 첫 필기 실행기는 펜 끝 기준 IK와 검증된 획 경로를 사용한다.
- 입력, 답변 생성, 필기 계획, 실행, 결과 검증을 나누어 단계별로 평가한다.
- 초기 음성 입력은 명시적으로 녹음을 시작하는 방식으로 시험한다. 이후 자동
  발화 감지를 붙여 자연스럽게 말을 걸면 반응하도록 확장한다.
- API 모델이나 음성 인식이 실패하면 실패 상태를 표시하고 필기 작업을 만들지 않는다.
- 구현과 검증 결과를 확인한 뒤 다음 단계로 넘어간다.
- 로봇 없이 개발하는 동안에는 고정 텍스트의 필기 기반을 우선한다. AI 답변과
  음성 인식의 통합은 실물 고정 문장 시험 M6 통과 뒤에 진행한다.
- 첫 실물 목표는 고정된 종이에 큰 글씨를 천천히 읽히게 쓰는 것이다.
  서예체의 미관, 작은 글씨, 빠른 대화 속도, 자동 펜 집기와 종이 교체는 제외한다.

기존 픽앤플레이스 스킬의 추가 확장은 이번 작업 범위에서 마무리하고 새 필기
스킬을 개발한다. 기존 README에 기록된 시뮬레이션 결과와 실물 미검증 상태는
그대로 구분한다. 이번 결정은 미완료 실물 검증을 완료 처리한다는 뜻이 아니다.

## 3. 참고 사례와 확인한 사실

참고 링크: [SO-101 붓 그림 사례](https://x.com/cdngdev/status/2097339677128982873).

영상 주요 장면에서는 붓을 장착한 로봇팔, 테이프로 고정한 종이, 팔레트, 여러
시도의 그림 결과를 확인했다. 제작자는 SO-101을 사용했다고 설명했다.

[제작자의 후속 설명](https://x.com/cdngdev/status/2097339677745516710)에 따르면
약 1분 분량의 행동을 계획하고 실행 중 관찰하며 조정했다. 사람이 초기 기준점과
피드백을 제공했고 이후 보정을 조정했다고 설명한다. 공개 영상만으로 제어 코드,
모델 가중치 재학습 여부, 실제 실행 속도나 정확도를 확인할 수는 없다.

따라서 이 사례는 작업 구성의 참고 자료로 사용한다. 같은 성능이 우리 장비에서
재현됐다고 취급하지 않는다. 붓펜은 잉크를 포함하므로 첫 버전에서 팔레트와 물감
보충 동작을 줄일 수 있다.

## 4. 전체 흐름과 모듈 경계

```text
음성 입력
  -> 음성 인식: 사용자가 한 말
  -> 답변 생성: 질문에 맞는 한글 한 문장
  -> 답변 검사: 지원 문자, 길이, 남은 공간
  -> 필기 계획: 자모/음절 배치, 획 순서, 펜 올림/내림
  -> 실행 전 검사: 경로, 도달영역, 관절 한계, 보정 상태
  -> 실행: 화면 미리보기 / 로봇 시뮬레이션 / 실제 로봇
  -> 결과 확인: 실행 상태와 필기 이미지
  -> 기록 저장 및 대기 상태 복귀
```

| 모듈 | 역할 | 로봇 없이 개발 가능한 범위 |
| --- | --- | --- |
| 음성 입력/인식 | 녹음, 한국어 변환, 무음 처리 | 노트북 마이크로 시험 |
| 답변 생성 | 질문 이해, 한 문장 답변 생성 | 텍스트 질문부터 시험 |
| 답변 검사 | 문자 지원과 문장 길이, 공간 검사 | 완전 오프라인 시험 가능 |
| 필기 계획 | 종이 좌표의 획과 펜 상태 생성 | 완전 오프라인 시험 가능 |
| 실행기 | 계획을 각 실행 환경으로 전달 | 미리보기와 시뮬레이션 개발 |
| 결과 검증 | 누락 획, 영역 이탈, 문자 내용 확인 | 인터페이스와 저장 이미지 시험 |
| 작업 관리자 | 중복 방지, 중지, 오류 처리, 진행 기록 | 가짜 실행기로 시험 |

System 2는 질문과 답변 및 작업 전략을 담당한다. System 1에는 새 필기 제어
스킬을 연결한다. 기존 ACT 픽앤플레이스 정책이 필기를 수행한다고 가정하지 않는다.
필기 경로와 낮은 수준의 관절 명령은 실행기가 관리한다.

## 5. 현재 코드에서 재사용할 부분과 필요한 변경

| 구성 요소 | 확인한 상태 | 필기용 작업 |
| --- | --- | --- |
| `kwon_lab/skills/primitives.py` | IK의 기준은 `gripperframe` | 실제 펜 끝 위치/방향을 표현하는 도구 모델 추가 |
| `kwon_lab/hardware/real_so101_adapter.py` | 관측, 단위 변환, 상대/절대 제한, 감사 기록 구현 | 필기 실행 경로 연결과 실제 매핑 검증 |
| `kwon_lab/hardware/real_preflight.py` | 기존 작업의 필수 보정/장소/안전 검사 | 기존 보호 장치를 유지하며 필기 조건 추가 |
| `kwon_lab/skills/registry.py` | 스킬 계약과 시간 예산 관리 | 필기 스킬의 전제조건, 검증, 중지 처리 등록 |
| `kwon_lab/orchestrator/system2.py` | 시뮬레이션 픽앤플레이스 도구 흐름 | 답변 생성과 필기 작업 흐름을 분리해 연결 |
| `kwon_lab/orchestrator/voice_cockpit.py` | `mlx-whisper`, `termios`, `say`, `afplay` 등 Mac 전용 부분 존재 | Windows 음성 입력 경로 구현 |

관절 구성은 팔 관절 5개와 그리퍼 1개다. 필기 중 그리퍼 상태를 유지하면서
펜 위치와 기울기를 만족하는 영역을 찾는다. 위치가 도달 가능해도 모든 펜 자세가
도달 가능한 것은 아니므로 시뮬레이션과 실물에서 각각 검사한다.

## 6. 현재까지 구현한 내용

현재 완료한 것은 **입력한 한글 문장을 화면 필기 경로로 바꾸는 오프라인 기반**이다.

| 항목 | 현재 상태 |
| --- | --- |
| 한글 획 생성 | 현대 한글 음절, 호환 자모, 공백과 일부 문장부호 지원 |
| 입력 정규화 | Unicode NFC 정규화 적용 |
| 배치 | 가상 종이 크기, 여백, 글자 크기/간격, 자동 줄바꿈 |
| 경로 검사 | 미지원 문자, 영역 초과, 비정상 숫자 입력 거부 |
| 실행 데이터 | 종이 기준 mm 좌표와 펜 이동/내림/획/올림 작업 |
| 출력 | PNG, SVG, 획 순서 애니메이션, JSON |
| 테스트 | 8개 통과, 현대 한글 11,172개 음절의 유한값/영역 검사 포함 |
| 가독성 검수 | 예문 이미지 확인; 사용자 검수와 글자 개선은 진행 예정 |
| 음성 인식 | 미구현, 현재 가상환경에 STT 패키지 없음 |
| 질문별 AI 답변 | 미구현, 확인한 실행 환경에 답변 모델 키 미설정 |
| 로봇 시뮬레이션 | 필기용 펜 모델과 실행기 미구현 |
| 실제 로봇 필기 | 미구현, 장비 연결/보정 미완료 |
| 카메라 필기 검증 | 미구현 |

관련 파일:

- `kwon_lab/writing/strokes.py`: 단순 중심선 글자 형상.
- `kwon_lab/writing/planner.py`: 입력 검사, 배치, 샘플링, 계획 데이터.
- `kwon_lab/writing/preview.py`: 이미지와 SVG/JSON 출력.
- `kwon_lab/tools/writing_preview.py`: 실행 도구.
- `tests/test_writing.py`: 오프라인 검증.

예문 산출물은 Git 비추적 `outputs/writing/first_sentence/`에 있다.
예문은 `오늘은 어떤 일을 도와드릴까요?`이며 AI가 질문에 답한 결과가 아니라
획 생성 시험에 직접 입력한 문장이다.

이 획 라이브러리는 단순한 중심선 글꼴이다. 붓글씨 모델, 실제 필압 제어,
전통적인 운필 순서가 구현됐다는 의미는 아니다. 숫자, 영어, 이모지, 지원 목록
밖의 문장부호는 현재 명시적으로 거부한다.

## 7. 로봇 없이 먼저 진행할 마일스톤

### M0. 필기 계획과 화면 검수

상태: 경로 생성과 미리보기 구현 완료, 사용자 가독성 검수 남음.

- [x] 한글 획, 배치, 펜 올림/내림, PNG/SVG/JSON 출력 구현.
- [x] 오프라인 테스트 8개 통과, 현대 한글 11,172개 음절의 좌표 검사.
- [ ] `가`, `한`, `글`, 받침·복합 모음과 대표 문장의 미리보기 검수.
- [ ] 읽기 어려운 형상, 간격, 획 끊김을 수정하고 회귀 테스트 추가.

통과 기준: 사람이 대표 글자와 문장을 읽을 수 있고 여백·펜 상태 검사가 통과한다.
좌표 검사와 화면 가독성은 실물 가독성의 증거로 사용하지 않는다.

### M1. 펜 끝 기준 로봇 시뮬레이션

선행 조건: M0 통과. 상태: 미시작.

- [ ] MuJoCo에 가상 펜 끝과 종이 평면을 추가.
- [ ] 펜 끝 기준 IK, 가능한 기울기, 연속 관절 경로 구현.
- [ ] 관절 한계·충돌·도달 불가능 경로·속도·중지 검사.
- [ ] 선, 네모, `가`, `한`, `글`, 고정 문장을 순서대로 실행.

통과 기준: 가능한 영역에서 경로를 추종하고, 불가능하거나 위험한 경로는 거부한다.
2D 미리보기만으로 통과 처리하지 않으며 실제 잉크와 접촉 품질은 별도 평가한다.

### M2. 고정 텍스트 실행 관리와 시험 기록

선행 조건: M0 통과. M1과 연계해 검증. 상태: 미시작.

- [ ] `대기 -> 고정 텍스트 -> 계획 -> 검사 -> 실행 -> 확인 -> 대기` 흐름 구현.
- [ ] 동시에 한 작업만 실행하고 중지 시 추가 명령을 차단.
- [ ] 가짜 실행기로 정상·실패·중지·검증 불확실 상태 시험.
- [ ] 시험 ID, 설정, 계획, 실행 시간, 완료 획, 이미지와 판독 결과 저장 방식 구현.

통과 기준: 각 실행 결과와 중단 원인을 구분하고 반복 시험의 기록을 남길 수 있다.

### M6. 같은 고정 문장 10회 시험

선행 조건: M5 통과. 상태: 대기. **AI 답변과 음성 통합 전에 통과해야 하는 관문.**

설정을 바꾸면 이전 결과와 섞지 않고 10회 묶음을 다시 평가한다.

필기 시간은 접근 명령 시작부터 마지막 획 뒤 펜 올림 완료까지 측정하고,
대기 자세 복귀 시간은 별도로 기록한다. 최초 기준에는 임의의 속도 제한을 붙이지
않고 평균·최장 시간을 보고 다음 목표를 정한다. 사람이 물리 동작에 개입해
완성한 시도는 실패로 기록한다. 사람이 사전에 종이와 펜을 준비하는 것은 허용한다.

이 시험은 **그 문장과 설정의 반복 가능성**만 확인한다. 모든 한글 문장의 가독성이나
새 장착 상태의 성능을 증명하지 않는다. M7에서 다른 글자와 문장으로 평가를 넓힌다.

## 9. 실물 이식 시 유지할 계약

현재 `plan.json`은 종이 왼쪽 위 원점, 오른쪽 x, 아래쪽 y, 종이에서 멀어지는 z를
사용하는 mm 좌표다. 실제 관절 명령이나 실제 힘 값이 아니다.

- 첫 이동은 임의의 로봇 자세에서 안전하게 접근하는 경로를 정의하지 않는다.
- `z=0`은 가상 접촉 기준이다. 실제 접촉 높이와 눌림량은 보정해야 한다.
- 현재 기본 종이 크기와 펜 올림 높이는 미리보기 설정이며 실물 검증값이 아니다.
- 화면 애니메이션의 12초는 시연 시간이고 실제 제어 속도가 아니다.
- JSON에는 `motion_authorized=false`, `physical_calibration_required=true`가 남는다.
- 실제 실행기는 보정, 사전검사, 관절 한계, 실행 중 상태를 독립적으로 검사한다.
- JSON 플래그 변경만으로 실제 동작을 허용하지 않는다.
- 보정된 펜/종이 좌표와 시뮬레이션 특권 정답 상태를 구분한다.

소프트웨어에서 만든 같은 글자 경로를 재사용하되, 실제 실행에는 별도의 백엔드와
검증된 보정이 필요하다. 설정 하나를 바꾸면 실물에서 완성된다고 가정하지 않는다.

## 10. 보류 사항과 현재 다음 작업

아직 확정하지 않은 사항은 붓펜 모델과 고정 장치, 실제 작업영역, 답변 모델,
음성 인식 모델, 최종 글자 크기와 문장 길이, 실제 압력 제어 방식이다.
현재 소프트웨어 개발을 시작하는 데 로봇 연결은 필요하지 않다.

다음 작업은 M0의 미리보기 검수와 M1/M2의 필기 기반 구현이다.
장비 연결이 불가능한 동안 M3~M6은 대기 상태로 유지한다. 이를 건너뛰거나
미리보기만으로 실물 시험을 완료 처리하지 않는다. AI 답변 M7과 음성 인식 M8의
통합은 M6 통과 뒤 진행하고, 단계별 실제 검증 결과를 이 문서에 갱신한다.

## 11. Git과 산출물 관리

초기 계획과 구현은 로컬 미커밋 파일로 보관했다. 2026-10-07 사용자가 현재 단계의
README 기록과 브랜치 푸시를 요청했다. 새 필기 코드·테스트·문서를 해당 브랜치에서
커밋해 기록하며 `main` 병합과 PR 생성은 별도 요청 전까지 수행하지 않는다.
GitHub의 별도 Milestones 기능 대신 저장소 Markdown으로 진행 상태와 날짜를 관리한다.
푸시 결과와 커밋은 실제 Git 상태로 확인한다.

코드/문서는 검토 후 버전 관리 대상으로 하고, 실행 산출물은 기존 규칙에 따라
`outputs/`에 보관한다. 비밀정보와 검증되지 않은 실물 설정을 공개 문서에 넣지 않는다.

네트워크 참고: 학교 Wi-Fi에서는 X 영상 재생에 실패했고, 모바일 데이터 및
핫스팟 전환 후 재생됐다. 학교의 특정 차단 정책까지 확인한 것은 아니다.
온라인 모델 연결이 실패하면 실행 환경과 네트워크 상태를 구분해 점검한다.
