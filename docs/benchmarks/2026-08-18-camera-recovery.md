# 2026-08-18 카메라 기반 픽앤플레이스·복구 벤치마크

## 목적

상단 카메라와 손목 카메라만으로 `PICK → TRANSPORT → PLACE`를 수행하고, 집기 실패 또는 운반·PLACE 중 낙하가 발생하면 빈 운반을 계속하지 않고 다시 `PICK`으로 복귀하는지 확인한다.

## 제어와 채점의 분리

- 런타임 제어 입력: 상단 RGB, 손목 RGB, 로봇 관절 상태
- 런타임에서 사용하지 않는 값: MuJoCo 블록 위치·높이·목표 정답좌표
- MuJoCo 정답값은 시험 종료 후 성능 채점과 진단에만 사용
- 실제 로봇 적용 전 상단 카메라 픽셀→작업대 좌표 보정이 필요

## 구현된 상태 전이

1. 상단 카메라 블록 탐색
2. 손목 카메라 정밀 조준 후 픽
3. 다중 프레임 영상·그리퍼·팔 이동으로 픽 성공 확인
4. 상단·손목 카메라를 25Hz로 확인하며 운반
5. 14cm 접근 후 6cm 하강·상단 영상 정렬·릴리스
6. 팔을 목표 밖으로 후퇴시킨 뒤 75% 이상 포함과 정지를 10프레임 확인
7. 릴리스 전 낙하 또는 최종 판정 실패 시 `PICK`으로 복귀
8. `DONE` 또는 기본 4회 안전 한도에서 종료

## 최종 결과

| 시험 | 표본 | 결과 |
|---|---:|---|
| 정상 전체 픽앤플레이스 | 선택한 3개 시작 조건 | 3/3 `DONE`, 실제 포함률 모두 100% |
| 정상 운반 낙하 오탐 | 동일 3개 조건 | 0/3 |
| PLACE 중 강제 낙하 | 선택한 3개 시작 조건 | 3/3 감지, 의도적 릴리스 차단, `PICK` 복귀 |
| 정상 자동 반복 루프 | 선택한 1개 조건 | 1회차 `DONE`, 복구 0회, 실제 포함률 100% |
| 강제 낙하 자동 복구 | 선택한 1개 조건 | 1회차 낙하 감지, 2회차 재픽·재운반·PLACE, 실제 포함률 82.93%, `DONE` |

강제 낙하 복구에서 블록이 옆으로 쓰러져 중심 높이가 약 2cm가 됐다. 복구 픽은 상단 위치를 다시 측정하고 `2cm 중심 높이`, 작은 XY 보정, 손목 회전 후보를 순서대로 사용한다. 각 후보는 픽 이후 손목 영상과 관절을 이용한 강한 검증을 통과해야만 운반으로 넘어간다.

## 성공 판정 수정

기존 MuJoCo 채점은 블록이 쓰러져도 항상 4×4cm 바닥면으로 계산했다. 이를 현재 자세에서 가장 수평인 실제 접촉면으로 변경했다.

- 세워진 블록: 4×4cm
- 옆으로 쓰러진 블록: 4×6cm
- 수정 전 특정 쓰러진 배치: 잘못된 100%
- 수정 후 동일 배치: 69.74%
- 같은 배치의 상단 카메라 추정: 약 71.5%

## 해석과 한계

- 결과는 MuJoCo의 선택된 소표본이며 실제 로봇 성공률이 아니다.
- 정상 3/3과 자동 복구 1/1을 일반적인 100% 성공률로 표현하면 안 된다.
- 쓰러진 블록 복구 후보는 현재 관측한 낙하 자세에 맞춰졌으므로 다양한 위치·회전에 대한 추가 검증이 필요하다.
- 다음 권장 검증은 정상 10회, 운반 낙하 10회, PLACE 낙하 10회이며 이후 50회 평가로 확대한다.
- 실제 로봇에서는 카메라 보정, 조명 변화, 렌즈 왜곡, 모터 오차, 충돌 안전 한도를 별도로 확인해야 한다.

## 두 시야 자세 선택·블록 자세 분류 업그레이드

복구를 시작할 때 그리퍼를 열고 엔드이펙터를 20cm까지 수직 후퇴한 뒤, 작업영역 양쪽에 둔 `CLEAR_VIEW_A/B` 중 하나로 이동한다. 마지막으로 보인 블록의 반대편 자세를 먼저 선택하고 상단 영상 5프레임의 검출 면적, 윤곽 형상비, 좌표 안정성, 작업영역 포함 여부를 점수화한다. 점수가 부족하면 반대 자세로 바꾸고 다시 관측한다.

- 서 있는 4×4×6cm 블록: 상단 형상비 약 1.00, `UPRIGHT`, 복구 중심 높이 3cm
- 쓰러진 블록: 상단 형상비 약 1.48, `TIPPED`, 복구 중심 높이 2cm
- 가림 또는 중간 형상비: `UNKNOWN`, 다른 자세에서도 불명확하면 집기를 시작하지 않음

선택 검증은 서 있음 3위치, 쓰러짐 3위치, 첫 자세 강제 가림, 양 자세 강제 가림의 8조건 모두 통과했다. 한쪽을 가린 조건에서는 `CLEAR_VIEW_B`에서 `CLEAR_VIEW_A`로 자동 전환했고, 양쪽을 모두 가린 조건에서는 `UNKNOWN`으로 안전 중단했다.

전체 루프 회귀에서 정상 조건은 1회차에 완료되어 실제 포함률 100%였다. PLACE 중 강제 낙하 조건도 최종 완료됐지만, 2회차 PLACE 확인이 실패해 다시 PICK으로 복귀한 뒤 3회차에 완료됐다. 최종 실제 포함률은 98.25%다. 따라서 이번 결과는 복구 루프가 끝까지 이어진다는 증거지만, PLACE 재시도 횟수가 개선됐다는 증거는 아니다.
