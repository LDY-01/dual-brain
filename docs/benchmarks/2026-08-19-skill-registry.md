# 2026-08-19 최소 S6 스킬 레지스트리 검증

## 목적

픽앤플레이스를 먼저 완성한 뒤 다시 구조를 뜯어고치지 않도록, 기존 카메라 기반 동작을 변경하지 않고 최소 공통 스킬 규격으로 감쌌다. 실물 능동 동작은 수행하지 않았다.

## 구현 범위

- `SkillSpec`: 실행 함수, 사전조건, 성공 판정기, 상태 효과, 제한시간, 복구 계획
- `SkillRegistry`: 이름 기반 등록·조회, 중복·누락 복구 스킬 검사
- `SkillExecutor`: 사전조건 차단, 실행 결과 판정, 제한시간 초과 거부, 한정된 복구 계획 실행, JSONL 감사 로그
- 픽앤플레이스 등록 스킬: `observe_target`, `pick`, `recover_pick`, `transport`, `place_6cm`

실행기의 제한시간은 실행이 끝난 뒤 계약 위반을 판정하는 추가 게이트다. 로봇 함수를 별도 스레드에서 강제 종료하지 않으므로 각 스킬 내부 반복문과 안전 한계는 계속 유한해야 한다.

## 검증 결과

| 검증 | 결과 |
|---|---:|
| 물체를 들지 않은 운반 호출 차단 | 통과 |
| 실패한 픽의 선언형 복구 실행 | 통과 |
| 복구 효과의 상태 반영 | 통과 |
| 복구 뒤 운반 실행 | 통과 |
| 제한시간 초과 결과 거부 | 통과 |
| MuJoCo 정상 픽앤플레이스, 시드 9101 | 성공, 실제 포함률 100% |
| PLACE 중 강제 낙하 | 감지 성공 |
| `재집기 → 운반 → 6cm 놓기` 선언형 복구 | 성공, 실제 포함률 100% |

강제 낙하된 블록은 `TIPPED`로 판정됐고 복구 픽 중심 높이를 2cm로 바꿔 다시 집었다. 최종 카메라 성공 판정과 MuJoCo 정답 판정이 모두 성공했다.

## 현재 경계

이 결과는 S6 완료가 아니라 **최소 골격과 픽앤플레이스 연결 완료**를 의미한다. 다음 항목은 아직 남아 있다.

1. System 2가 하드코딩된 도구 목록 대신 레지스트리를 조회하도록 연결
2. `return_home`, `emergency_stop` 등록 및 안전 우선순위 고정
3. 실물 실행 어댑터의 읽기 전용 그림자 모드에서 같은 실행 계획 검증
4. 새 장소 최초 픽 결과를 반영한 사전조건·제한시간·복구 규칙 조정

공개용 요약 수치는 [`skill_registry_summary.json`](../../benchmarks/results/2026-08-19/skill_registry_summary.json)에 저장한다. 단계별 원시 JSON과 JSONL 감사 로그는 `outputs/skill_registry/`에 로컬 보관한다.
