하루 동안 "시뮬 속 SO-101이 블록을 집는다"에 도달하기까지의 전 과정 기록.
통합 영상: [media/grasp_journey.mp4](media/grasp_journey.mp4) (32초, 실패 5개 → 성공 순서)

## 0. 최종 시스템이 도는 원리 (결론부터)

pick/place는 전부 IK(역기구학) 기반이다. 계층은 다음과 같다.

```
pick_at(x, y, z)                    ← System 2(Claude)가 호출하는 도구
  └─ pick()                        ← 검증된 그랩 레시피 (아래 4단계)
       ├─ move_to(접근점, 45°)      ← 각 단계가 IK 호출
       ├─ move_to(삽입점)          ← 손가락 축 방향으로 미끄러져 들어감
       ├─ set_gripper(닫기)
       └─ move_to(리프트)
            └─ solve_ik()          ← 야코비안 감쇠최소제곱(DLS) 반복
                 └─ data.ctrl[:]   ← 위치제어 모터가 관절각 추종 (실물과 동일 의미)
```

solve_ik의 원리: "목표와 손끝의 오차를 재고 → 각 관절을 미소 회전시켰을 때
손끝이 움직이는 방향표(야코비안)를 계산 → 오차가 줄어드는 방향으로 관절각을
조금 수정"을 최대 300회 반복. 보통 1~2mm 오차로 수렴한다.
방향 제어가 필요하면(그랩 자세) 위치 3차원 + 손가락축 정렬 3차원 = 6차원 오차를
함께 푼다. 코드: `kwon_lab/skills/primitives.py`의 `solve_ik()`.

핵심 상수 (전부 실측으로 얻음):
- 접근 각도 45° — 완전 수직(90°)은 팔 길이상 도달 불가 영역이 넓음
- 포켓 오프셋 (-3cm, 0, +1cm) — 손끝 기준 "진짜 잡히는 지점"의 위치
- 삽입 거리 6cm — 벌린 입이 물체를 삼키는 활주 거리

## 1. 실패의 연대기

### 시도 1 — 방향 없는 IK (영상 0:00~0:05, media/first_move_to.mp4)

- 시도: 위치만 맞추는 3차원 IK로 접근→하강→닫기→리프트
- 결과: 손끝 위치는 1.4mm 오차로 정확했으나 손목이 아무 방향이나 향함.
  손가락이 블록을 감싸는 자세가 아니라 옆구리로 침. 블록 높이 15mm(바닥 그대로)
- 교훈: 위치만으로는 부족하다. 방향도 IK의 목표에 넣어야 한다
- 증거: [media/grasp_debug.png](media/grasp_debug.png) — 닫는 순간 손가락이 블록 왼쪽 허공

### 시도 2 — 수직 하향 자세 (영상 0:05~0:11, media/pick_v2.mp4)

- 시도: 손가락축을 (0,0,-1)로 정렬하는 6차원 IK
- 결과: IK 오차 239mm — 수렴 실패. 5자유도 팔은 멀리 있는 물체를 완전 수직으로
  내려찍을 수 없다 (도달 가능 영역 밖)
- 교훈: 로봇마다 자세의 기하학적 한계가 있다. 실물 SO-101 데모들이 비스듬히
  잡는 이유가 이것

### 시도 3 — 45° 기울임 + 하강만 위치 IK (media/pick_v4.mp4)

- 시도: 접근 때만 45° 방향을 잡고, 하강은 순수 위치 IK (기울인 자세에서 출발하면
  가장 가까운 해가 자세를 대략 유지)
- 결과: IK는 전 구간 1~6mm로 수렴. 그러나 닫는 순간 블록이 2.3cm 밀려남.
  그리퍼 관절이 거의 끝까지 닫힘(0.08/0.10) = 허공을 쥠
- 교훈: 위치·방향이 다 맞아도 접촉의 기하가 틀리면 실패한다
- 증거: [media/grasp_closeup.png](media/grasp_closeup.png) — 고정 손가락 끝이 블록
  '위'를 찍고 움직이는 턱은 저 위에 열려 있음

### 시도 4 — 자동 파라미터 탐색 (턱 방향 실측 오프셋 포함, media/pick_v5.mp4)

- 시도: 사람 손튜닝을 중단하고 각도×깊이×높이×닫힘값 조합을 기계적으로 탐색.
  1차 120회(광역) + 2차 100회(수직 근처 집중) = 220회
- 결과: 전멸 (성공 0/220)
- 교훈: 충분히 넓은 탐색이 전멸하면 파라미터 문제가 아니라 구조 문제다.
  "파라미터를 의심하기 전에 가정을 의심하라"

### 결정 실험 — 텔레포트 테스트

- 시도: 접근 궤적을 전부 배제하고, 블록을 손가락 사이 45개 지점에 순간이동시킨 뒤
  닫고 들기만 시험
- 결과: 0/45. 어떤 위치에서도 쥘 수 없음 → 이 모델은 물리적으로 그랩 불가로 확정
- 이것이 이날의 가장 중요한 실험이다. 원인 후보를 "궤적"에서 "모델"로 옮겼다

### 범인 — 볼록 껍질(convex hull) 충돌

- MuJoCo는 메시 충돌을 기본적으로 볼록 껍질로 계산한다. 오목한 손가락 안쪽 곡면이
  전부 메워져, 시각적으로는 손가락이지만 물리적으로는 벙어리장갑이었다
- 물체가 낄 공간이 충돌 세계에는 존재하지 않았으므로 어떤 궤적·파라미터로도
  불가능했던 것
- 증거: [media/collision_hulls.png](media/collision_hulls.png) — 엔진이 실제로 쓰는
  충돌 형상 렌더

### 해결 — Menagerie 모델 교체

- DeepMind가 큐레이션하는 MuJoCo Menagerie의 `robotstudio_so101`은 손가락 충돌을
  얇은 박스·구·캡슐 프리미티브로 수작업 배치했고, 그랩용 접촉 파라미터(마찰 condim=6,
  priority)까지 튜닝되어 있으며, "잡고 있는 상태" 키프레임으로 검증까지 동봉
- 교체 후 동일 텔레포트 테스트: 37/45 성공. 부산물로 포켓 오프셋 (-3cm,0,+1cm) 실측

### 마지막 함정과 최종 레시피 (영상 마지막, media/first_pick_and_place.mp4)

- 새 모델에서도 위에서 수직으로 내리면 손가락이 블록을 먼저 때려 밀어냄
- 해법: 클로 머신 방식 — 벌린 입을 물체 뒤쪽 6cm에서 손가락 축 방향으로 미끄러뜨려
  물체를 삼킨 뒤 닫는다. 삽입 시 블록 이동 0mm
- 최종 성적 (10개 랜덤 위치): 그랩 10/10, 픽앤플레이스 7/10
  (실패 3건은 전부 내려놓을 때 튐 — System 2 재시도 로직의 소재)

## 2. 이중시스템 첫 가동 (media/s3_first_command.mp4)

- "빨간 블록을 초록 목표 구역으로 옮겨줘" 한 문장으로 Claude(System 2)가
  observe→pick_at(좌표 전달)→place_at→재관찰 검증→done 수행. 최종 오차 49mm(반경 내)
- 방해물(파란 공)을 건드리지 않았고, 자기 보고와 물리 판정이 일치했다
- 실행 로그: outputs/s3_transcript.json

## 3. 전이 가능한 교훈 목록

1. 위치 IK → 방향 IK → 접촉 기하 → 충돌 모델. 실패는 항상 한 층 아래에 있었다
2. 손튜닝 몇 번 실패하면 즉시 자동 탐색으로. 탐색이 전멸하면 가정 검증 실험으로
3. 시뮬의 특권(순간이동, 좌표 판정)을 진단 도구로 적극 활용하라
4. 시각 형상과 충돌 형상은 다르다. 그랩이 안 되면 충돌 형상부터 렌더해봐라
5. 검증된 모델(Menagerie 등)이 있으면 직접 고치기 전에 먼저 찾아라
6. 성공한 레시피는 즉시 함수로 봉인하고 성공률을 수치로 남겨라
