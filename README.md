### 2026-08-19 실물 블록 물성 반영

실물 빨간 블록은 **3D 프린터로 제작한 무광 PLA 출력물**이다. 제공된 STEP을 직접 검사해 40×40×60mm, 전 모서리 R1mm를 확인하고 0.02mm 허용오차의 MuJoCo 메시로 변환했다. 질량은 실측 28.6g으로 변경했다. 제공된 Bambu Studio 화면은 실제 출력 작업의 설정과 동일한지 확인되지 않았으므로 참고 정보로만 기록하며, 책상 마찰도 아직 측정값이 없어 0.25–0.80 범위를 시드 고정 무작위화로 적용했다.

2026-08-20부터 사용할 새 작업대 표면은 **흰색 무광 세라믹**이다. 기존 작업대의 라미네이트 계열 추정은 더 이상 현행 조건이 아니다. 세라믹 표면은 확정했지만 실제 PLA 블록과의 마찰은 측정하지 않았으므로 시뮬레이션 마찰 범위는 그대로 유지한다. 장소 변경 후 로봇·기둥 배치를 먼저 고정하고 카메라 보정과 숄더팬 안전 한계를 새 환경에서 다시 측정한다.

장소 이전에 대비해 [새 작업공간 실물 전환 절차](docs/real-workspace-commissioning.md)를 구현했다. 실제 연결 검사에서 노트북 내장 카메라는 index 0, 손목 U20CAM은 index 1, 상단 U20CAM은 index 2로 확인했다. 동일 모델 두 대는 한 대씩 분리 연결해 PnP ID를 구분했고 두 역할의 로컬 등록과 1280×720 실시간 검사를 통과했다. 배치 ID가 일치하는 숄더팬 한계와 상단 보정, 현장 안전 확인은 하나의 프리플라이트로 검사하고, 통과 후 최초 픽 10회의 전후 영상과 실패 원인을 기록한다. 재현 시드 1908의 상단 인식 200조건에서는 정상 50/50, 조명 변화 47/50, 부분 가림 47/50을 검출했고 행동 가능한 자세 오판은 부분 가림에서 0건이었다. 카메라 위치가 바뀐 채 옛 보정을 쓰면 XY 오차 p95가 44.05mm로 증가해 새 장소 재보정이 필수임을 확인했다. 추가 시드 20260819는 조명 변화 XY p95가 15.65mm로 15mm 기준을 근소하게 넘어 전체 게이트가 실패했으므로, 현재 강건성은 충분한 여유가 있다고 볼 수 없다. 상세 결과는 [실물 전환 소프트웨어 검증](docs/benchmarks/2026-08-19-real-transition-software.md)에 있다.

실제 상단 프레임에서는 화면 가장자리의 빨간 포장지가 블록 마스크에 함께 들어오는 문제가 발견됐다. 인식기를 연결요소 단위로 분리해 테두리에 닿는 빨간 잡동사니보다 독립된 블록 후보를 우선하도록 수정했고, 같은 프레임에서 블록만 7,946픽셀로 분리했다. 수정 후 시뮬레이션 회귀 40조건은 모두 통과했다. 실제 자세 분류는 현재 카메라가 수직이 아니어서 유효하지 않으며 새 장소 수직 설치·보정 후 다시 검증한다.

같은 시드 5000–5049에서 현재 코드로 다시 비교한 결과, 기존 96g 조건과 실물 반영 조건 모두 전체 성공 16/50(32%)이었다. 집기 확인은 32/50 대 34/50, 평균 최종 거리는 10.726cm 대 10.734cm였다. 28.6g 변경이 성능을 추가로 떨어뜨렸다는 근거는 없지만, 현재 정책의 절대 성능은 개선이 필요하다. 전체 궤적을 무조건 다시 학습하지 않고 실제 최초 픽과 전체 작업을 저속 실행해 실패 구간을 나눈 뒤, 집기 또는 운반·놓기 구간을 선택적으로 파인튜닝한다. 상세 조건은 [2026-08-19 실물 블록 물성 벤치마크](docs/benchmarks/2026-08-19-red-block-physics.md)에 정리했다.

### 실물 실행 소프트웨어의 현재 경계와 다음 작업

카메라 기반 상태 머신은 `PICK → PICK_VERIFY → TRANSPORT → PLACE → PLACE_VERIFY → DONE`을 실행하고, 집기 실패·운반 중 낙하·시야 가림·놓기 실패 시 다시 `PICK`으로 돌아가는 복구 흐름까지 MuJoCo에서 연결되어 있다. 카메라 역할 등록, 새 작업공간 프리플라이트, 관절 명령 제한 및 최초 픽 10회 증거 기록기도 준비했다.

MuJoCo 환경과 같은 6관절 라디안 관측·액션 인터페이스를 실제 SO-101 위에 제공하는 **실물 실행 어댑터**를 구현했다. 실제 관절값과 손목·상단 RGB를 읽고, ACT 출력을 LeRobot의 팔 관절 도·그리퍼 0–100 범위로 변환한 뒤 명령당 5단위 상대 제한과 숄더팬 절대 제한을 적용한다. 그림자 모드는 같은 변환과 안전검사를 수행하지만 직렬 버스를 읽기 전용으로 열고 `send_action`과 Goal Position을 호출하지 않는다.

가짜 로봇·카메라 회귀시험에서는 그림자 모터 전송 0회, 정책↔실물 관절 변환 왕복, 1280×720→640×480 중앙 크롭, 프리플라이트 차단과 상대·절대 제한이 모두 통과했다. ACT v2.2 체크포인트도 CPU에서 6관절 유한값을 출력했다. 그러나 실물 관절 좌표 방향과 영점은 아직 새 장소에서 대조하지 않았으므로 모든 매핑을 `verified_on_physical_robot=false`로 유지한다. 실제 프리플라이트와 여섯 관절 매핑이 모두 확인되기 전에는 능동 모드 생성 자체가 실패한다. 상세 절차는 [실물 실행 어댑터와 그림자 모드](docs/real-policy-adapter.md)에 있다.

### 다음 실물 전환 흐름

1. 새 장소에서 로봇·손목 카메라·상단 카메라 배치를 고정하고 카메라 역할, 상단 호모그래피, 숄더팬 안전 한계를 다시 설정한다.
2. 실물 실행 어댑터를 연결한 뒤 먼저 읽기 전용 그림자 모드로 카메라 판정, ACT 제안 관절값, 단위 변환과 안전 제한을 확인한다.
3. 프리플라이트 통과 후 현재 모델로 저속 최초 픽 10회를 수행한다. 0–7회 성공이면 집기 파인튜닝 대상으로 판정하고, 8회면 10회를 추가하며, 9–10회면 전체 픽앤플레이스 검증으로 넘어간다.
4. 저속 전체 픽앤플레이스 10회의 단계별 실패를 분류한다. 집기 실패는 집기 데이터, 운반 중 낙하는 운반 데이터, 놓기 실패는 6cm 놓기 데이터로 각각 보강한다.
5. 파인튜닝 모델은 기존 v2.2와 같은 조건에서 비교 평가하고 명확히 개선된 경우에만 교체한다.

### 최신 카메라 상태 머신 검증

런타임 제어는 MuJoCo 물체 정답좌표를 사용하지 않고 상단·손목 RGB와 로봇 관절 상태만 사용합니다. MuJoCo 정답은 벤치마크 종료 후 채점에만 사용합니다.

| 검증 | 결과 | 해석 |
|---|---:|---|
| 정상 PICK→TRANSPORT→6cm PLACE | 3/3 | 모두 실제 접촉면 포함률 100%, 최종 `DONE` |
| PLACE 중 강제 낙하 감지 | 3/3 | 의도적 릴리스 전 중단 후 `PICK` 복귀 |
| 정상 자동 루프 회귀 | 1/1 | 복구 없이 1회차 `DONE`, 포함률 100% |
| 강제 낙하 후 자동 복구 | 1/1 | 2회차에 쓰러진 블록 재픽, 최종 포함률 82.93%, `DONE` |
| 두 시야 자세 자동 선택 | 8/8 조건 통과 | 서 있음 3위치·쓰러짐 3위치, 한쪽 가림 전환, 양쪽 가림 안전 중단 |
| 시야 선택 적용 정상 전체 루프 | 1/1 | 1회차 완료, 실제 포함률 100% |
| 시야 선택 적용 강제 낙하 복구 | 1/1 | 3회차 완료, 중간 PLACE 재확인 실패 1회, 최종 실제 포함률 98.25% |

표본 수가 작으므로 일반 성공률 100%를 뜻하지 않습니다. 상세 조건·한계와 공개용 최종 JSON은 [2026-08-18 카메라 복구 벤치마크](docs/benchmarks/2026-08-18-camera-recovery.md)를 참고하십시오.

## 프로젝트의 핵심 가설

일반적인 로봇 학습은 사람이 장시간 시연 데이터를 만들어야 합니다. 이 프로젝트는 그 선생을 사람에서 System 2로 교체합니다.

1. System 2가 새로운 명령을 이해하고 성공 조건과 행동 레시피를 설계합니다.
2. 시뮬레이션에서 레시피 또는 탐색기가 여러 번 시도합니다.
3. 외부 성공 판정기가 결과를 채점합니다.
4. 검증된 궤적을 LeRobot 형식의 학습 데이터로 저장합니다.
5. ACT 등의 System 1 정책이 카메라와 관절 상태만 보고 행동하도록 학습합니다.
6. 배포 시 반복 작업은 System 1이 빠르게 수행하고, 실패하거나 낯선 상황에서는 System 2가 개입합니다.

핵심 명제는 다음과 같습니다.

> 사람 시연 시간을 늘리는 대신, LLM이 실험을 설계하고 시뮬레이션이 데이터를 생산하며 성공 판정기가 품질을 관리한다.

## 이중 시스템 아키텍처

| 계층 | 실행 주기 | 역할 |
|---|---:|---|
| System 2 | 이벤트 단위, 약 0.2–0.3Hz | 자연어 명령 해석, 태스크 분해, 전략 수립, 성공 조건 작성, 스킬 선택, 실패 복구, 보고서 작성 |
| System 1 | 약 10–100Hz | ACT 같은 학습 정책과 IK·모션 플래닝 같은 고전 제어 스킬을 실행 |
| 서보·안전 | 100Hz 이상 | 관절 목표 추종, 토크 제한, 작업 공간 및 비상 정지 관리 |

System 2는 고주파수 제어 루프에서 매 동작을 직접 결정하지 않습니다. 파라미터 탐색은 CEM·랜덤 탐색 등의 수치 최적화기가 맡고, System 2는 탐색 범위·목표·검증기를 설계합니다. System 1의 각 스킬은 장기적으로 다음 정보를 포함하는 레지스트리 항목으로 관리합니다.

```text
skill = {
  policy_or_controller,
  preconditions,
  effects,
  success_verifier,
  timeout,
  recovery_strategy
}
```

## 에고센트릭 정책과 외부 감독 설계 원칙

2026-08-10부터 ACT 정책 입력에서는 세계 좌표 인터페이스를 폐기하고 손목 카메라 중심의 에고센트릭 구조로 전환했습니다. 이후 전체 작업 복구를 위해 상단 카메라를 정책 밖의 외부 감독기로 추가했습니다.

- ACT 모델 입력은 몸에 부착된 손목 카메라와 관절 상태를 사용합니다.
- 고정 `front` 카메라는 기존 ACT 모델 입력에는 넣지 않습니다. 현행 상단 카메라는 사람 관전뿐 아니라 집기·운반·놓기 검증, 낙하 감지, 재탐색과 복구 조준을 담당하는 외부 감독기로 사용합니다.
- 물체의 세계 좌표와 시뮬레이션 정답 상태는 외부 채점 및 선생 데이터 라벨링에만 사용합니다.
- 런타임 제어는 카메라 기준 상대 이동, 관절 직접 제어, 로컬 시각 조준 스킬로 수행합니다.
- 손목 카메라 영상의 FK·관절 엔코더 기반 자동 정립은 시뮬레이션 설계에 포함돼 있습니다. 실물 어댑터는 현재 카메라 읽기와 640×480 중앙 크롭까지 구현됐으며, 자동 정립은 새 장소에서 관절 매핑·기구학·실제 영상 방향을 확인한 뒤 연결하고 검증해야 합니다.
- 새 기능을 추가할 때도 채점·진단 목적 외에는 특권 좌표를 정책이나 LLM에 노출하지 않습니다.

이 결정의 배경은 고정 카메라 정책이 바닥과 조명을 바꾸자 성공률이 50%에서 15%로 떨어진 실험입니다. 몸에 붙은 카메라를 사용하면 외부 카메라 배치에 대한 구조적 의존을 줄일 수 있습니다.

## 현재까지 검증한 가설

| 가설 | 실험 | 1차 결과 |
|---|---|---|
| LLM이 사람 선생을 대체할 수 있다 | 레시피 선생이 생성한 시뮬레이션 데이터로 ACT 학습 | 초기 실험에서 학생 정책이 선생의 50% 성공률에 도달 |
| 특권 좌표 없이 손목 카메라로 조작할 수 있다 | 로컬 Gemma가 스캔→인식→센터링→레이캐스트→그랩 수행 | 손목캠 단독, 약 1.5cm 오차로 첫 그랩 성공, API 비용 $0 |
| 사전 지식 없이 몸을 발견할 수 있다 | 이름 없는 모터 6개와 카메라만 제공하는 `unknown body` 실험 | Claude가 17회 호출·약 2.6분에 인과지도를 만들고 블록 접촉 성공 |

로컬 VLM은 한 번에 정확한 픽셀을 지목하는 방식에서는 실패했지만, 거친 격자 판단을 반복하는 폐루프에서는 성공했습니다. 따라서 지각 모델의 원샷 정밀도보다 **관찰→조정→재관찰 루프의 설계**가 더 중요한 것으로 판단합니다.

## 에고센트릭 ACT 실험 결과

| 버전 | 관측과 시작 조건 | 성공률 | 해석 |
|---|---|---:|---|
| v1 | 고정 `front` 카메라, 기존 씬 | 50% | 선생 성공률을 재현했지만 씬에 강하게 종속 |
| v1 분포 이동 | 같은 정책, 새 바닥·조명 | 15% | 외부 카메라 기반 정책의 배치 민감성 확인 |
| v2 | 손목 카메라, 홈 자세 시작 | 5% | 첫 관측에 블록이 없으면 특권 지식이 학생에게 전달되지 않음 |
| v2.1 | 손목 카메라, 블록 조준 후 시작 | 25% | 가시성 확보만으로 성공률 5배 증가 |
| v2.2 초기 upstream 평가 | v2.1 조건, 성공 에피소드 200개 | 30% | 인수 전 평가 조건의 기록. 이후 평가 조건·코드가 달라 상단의 48%·32%와 직접 비교하지 않음 |

이 실험에서 얻은 가장 중요한 교훈은 다음과 같습니다.

- 학습 loss가 낮아도 관측에 없는 정보는 배울 수 없습니다.
- 데이터 양보다 태스크에 필요한 정보가 적절한 순간에 보이는지가 더 큰 지렛대입니다.
- 선생 궤적에 정확한 놓기와 실패 복구가 없으면 학생도 그 행동을 모방하기 어렵습니다. 이는 학생이 선생 성공률을 절대 넘을 수 없다는 수학적 상한이 아니라, 데이터가 제공하는 행동 범위와 품질이 실용적인 성능 한계를 만든다는 뜻입니다.
- 이 초기 실험 당시 병목은 파지 순간의 가림, 운반 중 목표 구역의 시야 이탈, 단일 프레임 관측의 움직임 정보 부족이었습니다. 현재는 양 카메라 복구 상태 머신까지 구현됐으며, 새 장소 카메라 보정·실물 관절 매핑·최초 픽 성공률과 sim-to-real 차이 측정이 우선 병목입니다.

### DAgger 교정 루프

DAgger(Dataset Aggregation)는 선생의 성공 궤적만 한 번 학습하고 끝내지 않고, **학생이 실제로 방문한 실패 상태에 대한 선생의 교정 행동을 다시 데이터에 추가하는 반복 모방학습 방법**입니다.

```text
초기 선생 데이터로 학생 학습
  → 학생 정책을 직접 실행
  → 학생이 빗나가거나 멈춘 상태 수집
  → 그 상태에서 선생이 해야 할 행동을 라벨링
  → 기존 데이터에 교정 데이터 추가
  → 재학습 및 재평가
```

일반 행동복제는 선생이 정상적으로 지나간 상태만 보기 때문에, 배포 중 작은 오차로 낯선 상태에 들어가면 복구하지 못하는 분포 이동 문제가 생깁니다. DAgger는 학생 자신의 실패 상태를 다음 학습 데이터로 사용해 이 문제를 줄입니다. 이 프로젝트에서는 집기·운반·놓기 실패별 균형 교정 50에피소드를 수집하고 파인튜닝까지 수행했지만 기존 v2.2보다 낮아 채택하지 않았습니다. 다음 DAgger는 실물 실패 상태가 확보된 뒤 짧은 교정 구간 중심으로 재개합니다.

## 구현된 제어 흐름

```text
자연어 명령

성공 판정의 의미는 **블록의 실제 접촉면 75% 이상이 반지름 5cm의 목표 구역 안에 안정적으로 들어온 상태**로 통일합니다. 구현은 관측 가능 범위에 따라 구분합니다.

- MuJoCo 정답 채점: 블록의 현재 회전을 반영한 접촉면 포함률 75% 이상이고 블록 중심 높이가 5cm 미만이어야 합니다. 환경 보상·데이터 생성·정책 벤치마크의 최종 채점에 사용합니다.
- 카메라 런타임 판정: 상단 영상에서 자세별 접촉면 포함률 75% 이상과 10프레임 연속 안정을 요구합니다. MuJoCo 정답좌표는 런타임 제어에 사용하지 않습니다.
- 실물 최종 판정: 같은 카메라 기준을 사용하되 새 장소 수직 설치·호모그래피와 실제 블록 영상으로 다시 검증해야 합니다.

### 놓기 높이 벤치마크

2026-08-11에 동일한 20개 시드로 엔드이펙터 놓기 높이 8·6·5·4cm를 각각 평가했습니다. 픽셀 렌더링만 생략하고 물리·IK·그랩·놓기·1초 안착 판정은 동일하게 유지했습니다.

| 엔드이펙터 높이 | 실제 블록 바닥 평균 높이 | 안정 성공률 | 평균 포함률 | 성공 시 평균 중심 오차 | 평균 IK 오차 |
|---:|---:|---:|---:|---:|---:|
| 8cm | 4.20cm | 80% | 86.9% | 1.61cm | 1.59mm |
| 6cm | 2.22cm | **85%** | **88.1%** | 1.77cm | 1.75mm |
| 5cm | 1.34cm | 80% | 86.0% | 2.28cm | 1.69mm |
| 4cm | 0.62cm | 80% | 85.1% | 2.55cm | 1.59mm |

종합 추천은 **6cm**입니다. 8cm가 성공한 경우의 중심 오차는 0.16cm 더 작았지만, 6cm가 안정 성공률과 전체 평균 포함률에서 가장 좋았습니다. 4–5cm는 테이블과 가까워질수록 블록을 누르거나 밀 가능성이 커지며 중심 오차가 증가했습니다. 작업자 승인에 따라 기본 `place()` 엔드이펙터 높이를 12cm에서 **6cm로 변경했습니다**.

6cm 적용과 함께 놓기 궤적을 `목표 위 안전 높이 이동 → 수직 하강 → 안정화 → 블록-엔드이펙터 오프셋 보정 → 릴리스 → 안착 대기 → 수직 이탈` 순서로 개선했습니다. 50개 고정 시드 검증에서 집기 성공률 94%, 전체 안정 성공률 86%를 기록했고, 성공한 43건의 목표 포함률은 모두 100%, 평균 중심 오차는 0.75cm였습니다. `place()`가 반환한 성공 여부와 추가 1초 안정화 후 판정의 불일치는 0건이었습니다.

성공 판정 경계도 별도로 확인했습니다. 테이블 위 중앙 배치는 성공, 중앙에 있지만 공중에 든 블록은 실패, 4cm 중심 오프셋에서는 블록 회전에 따라 포함률 71.7%는 실패·75.28%는 성공으로 판정되어 75% 면적 기준과 높이 조건이 함께 적용됩니다.

전이 가능한 디버깅 원칙은 다음과 같습니다.

1. 위치 IK, 방향 IK, 접촉 기하, 충돌 모델 순서로 한 층씩 확인합니다.

4. 시각 형상과 물리 충돌 형상은 별도로 확인합니다.
5. 성공한 레시피는 즉시 함수로 봉인하고 성공률을 기록합니다.

uv run lerobot-record --robot.type=so101_follower --robot.port=COM3 --robot.id=so101_follower --robot.cameras="{ front: {type: opencv, index_or_path: 1, width: 640, height: 480, fps: 30}}" --teleop.type=so101_leader --teleop.port=COM5 --teleop.id=so101_leader --dataset.repo_id=DY-01/<dataset_name> --dataset.single_task="Place the lens cap into the open box." --dataset.num_episodes=10 --dataset.episode_time_s=30 --dataset.reset_time_s=10 --dataset.push_to_hub=false --display_data=true
```

시연 영상은 성공한 동작만 보관합니다. 손이 화면에 오래 남거나, 집기·놓기가 실패했거나, 기계적 이상이 발생한 에피소드는 학습 데이터에서 제외합니다.

### ACT 학습

ACT(Action Chunking Transformer)는 카메라 영상과 현재 관절 상태를 입력으로 받고, 이후 관절 명령 묶음(action chunk)을 예측하는 정책입니다.

Google Colab T4 GPU에서 학습했습니다.

```bash
pip install -q "lerobot[training]==0.6.0"

lerobot-train \
  --dataset.repo_id=DY-01/lens_cap_into_box_version1 \
  --dataset.video_backend=pyav \
  --policy.type=act \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --output_dir=/content/drive/MyDrive/SO101/act_lens_cap_v1 \
  --job_name=act_lens_cap_v1 \
  --batch_size=8 \
  --num_workers=2 \
  --steps=5000 \
  --save_freq=1000 \
  --log_freq=50
```

초기 5,000 step 학습 후 동일 모델을 재개하여 총 20,000 step까지 학습했습니다.

| 항목 | 값 |
|---|---|
| 정책 | ACT |
| 총 학습 step | 20,000 |
| 최종 training loss | 약 0.16 |
| 모델 이름 | `act_lens_cap_v1` |

학습 loss는 시연 데이터를 얼마나 잘 재현하는지의 지표일 뿐, 실제 로봇 성공률과 같지는 않습니다. 실제 성공률은 rollout 평가로 측정합니다.

### 모델 보관

학습된 모델은 로컬에서 다음 폴더에 둡니다.

```text
models/act_lens_cap_v1/
```

이 폴더는 `model.safetensors` 등 대용량 가중치를 포함하므로 GitHub 일반 Git에는 올리지 않습니다. 원본은 Google Drive 또는 Hugging Face에 별도로 보관합니다.

### 자율 실행

자율 실행에는 팔로워와 카메라만 사용합니다. 실행 전에 카메라 구도, 상자·뚜껑 위치, 팔의 시작 자세를 학습 데이터 수집 시점과 최대한 일치시킵니다.

#### 홈 자세 복귀 원칙

앞으로 작성하거나 수정하는 모든 자율 실행·평가 코드는 rollout이 성공, 실패, 시간 제한 종료 중 어느 경우로 끝나더라도 **정책을 먼저 정지한 뒤 팔로워를 안전한 속도로 홈 자세로 복귀**시켜야 합니다. 홈 자세는 캘리브레이션의 0점이 아니라, 이 작업을 시작할 때 사용하는 사용자 지정 관절 자세입니다.

홈 복귀는 ACT 정책이 학습해서 수행할 동작이 아니라 별도 제어 로직으로 처리합니다. 통신 오류, 충돌 위험, 비정상 진동 또는 비상 정지가 감지된 경우에는 홈 복귀를 시도하지 않고 즉시 모터를 정지하거나 12V 전원을 분리합니다. 홈 관절값은 실제 로봇에서 충돌 없이 확인한 뒤 코드 설정값으로 관리합니다.

```bash
uv run lerobot-rollout --strategy.type=base --policy.path=/Users/doyounglim/Desktop/SO101/models/act_lens_cap_v1 --device=cpu --robot.type=so101_follower --robot.port=/dev/tty.usbmodem5B140307781 --robot.id=so101_follower --robot.max_relative_target=5 --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" --task="Place the lens cap into the open box." --duration=30 --display_data=false
```

`--robot.max_relative_target=5`는 한 번에 너무 큰 관절 명령이 들어올 때 제한하는 안전장치입니다. 경고가 나오더라도 값을 높이거나 제거하지 않습니다.

### 자율 실행 평가

LeRobot 0.6.0에서는 `lerobot-record`가 리더암 시연 수집용입니다. 학습 정책 평가와 자동 영상 기록에는 `lerobot-rollout --strategy.type=episodic`을 사용합니다.

평가 데이터셋 이름은 반드시 `rollout_`으로 시작해야 합니다.

```bash
uv run lerobot-rollout --strategy.type=episodic --policy.path=/Users/doyounglim/Desktop/SO101/models/act_lens_cap_v1 --device=cpu --robot.type=so101_follower --robot.port=/dev/tty.usbmodem5B140307781 --robot.id=so101_follower --robot.max_relative_target=5 --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" --task="Place the lens cap into the open box." --dataset.repo_id=DY-01/rollout_act_lens_cap_v1_mac --dataset.root=/Users/doyounglim/Desktop/SO101/lerobot_data/rollout_act_lens_cap_v1_mac --dataset.single_task="Place the lens cap into the open box." --dataset.fps=30 --dataset.num_episodes=10 --dataset.episode_time_s=30 --dataset.reset_time_s=10 --dataset.video=true --dataset.push_to_hub=false --dataset.streaming_encoding=false --dataset.encoder_threads=1 --strategy.reset_to_initial_position=true --display_data=false
```

#### 평가 진행 방식

1. 각 회차가 끝나면 정책을 정지하고, 별도 홈 복귀 제어로 팔을 안전한 시작 자세에 되돌린 뒤 상자와 뚜껑을 시작 위치에 되돌립니다.
2. 영상과 관절 로그가 별도 rollout 데이터셋에 저장됩니다.
3. 영상 검수 후 성공 여부를 표시합니다.
4. 성공률은 `성공 에피소드 수 / 완전한 평가 에피소드 수`로 계산합니다.

현재 CPU 추론 속도는 약 3–5Hz 경고가 발생할 수 있습니다. USB-C 허브 연결 카메라에서 프레임 시간초과가 발생할 수 있으므로 다른 USB 장치를 최소화하고, 평가 중에는 `--display_data=false`, `--dataset.streaming_encoding=false`를 사용합니다.

#### ACT v1 정식 평가 결과

2026-07-31에 macOS의 고정된 카메라·상자·뚜껑 위치에서 10개 에피소드를 평가했습니다.

| 회차 | 뚜껑 접근 | 뚜껑 집기 | 상자 접근 | 상자 투입 | 최종 결과 |
|---:|:---:|:---:|:---:|:---:|:---:|
| 1 | O | X | - | - | 실패 |
| 2 | O | O | O | O | 성공 |
| 3 | O | O | O | X | 실패 |
| 4 | O | O | O | X | 실패 |
| 5 | O | X | - | - | 실패 |
| 6 | O | X | - | - | 실패 |
| 7 | O | O | O | O | 성공 |
| 8 | O | X | - | - | 실패 |
| 9 | O | X | - | - | 실패 |
| 10 | O | X | - | - | 실패 |

- 전체 성공률: `2 / 10 = 20%`
- 뚜껑 접근 성공률: `10 / 10 = 100%`
- 뚜껑 집기 성공률: `4 / 10 = 40%`
- 집기 성공 후 상자 투입 성공률: `2 / 4 = 50%`
- 평가 데이터: `lerobot_data/rollout_act_lens_cap_v1_mac`
- 저장 결과: 10개 에피소드, 8,567 프레임

가장 큰 병목은 뚜껑 집기 단계입니다. 먼저 실패 영상에서 그리퍼의 접근 위치, 높이, 닫는 시점을 비교하고, 해당 실패 조건을 중심으로 보강 데이터를 수집합니다.

#### ACT v2 정식 평가 결과

2026-07-31에 v1과 같은 고정된 카메라·상자·뚜껑 위치에서 10개 에피소드를 평가했습니다.

- 전체 성공률: `2 / 10 = 20%`
- 평가 데이터: `lerobot_data/rollout_act_lens_cap_v2_mac`
- 저장 결과: 10개 에피소드, 8,529 프레임

v2는 100개 성공 시연으로 학습했지만 v1의 20%를 넘지 못했습니다. 따라서 다음 보강에서는 무작위 위치를 더 넓히기 전에, 성공·실패 영상에서 그리퍼 중심 위치, 접근 높이, 닫는 시점, 파지 후 들어 올림을 비교해 실패 원인을 먼저 특정합니다.

#### ACT v2 홈 자세 평가 결과

2026-08-04에 실제 태스크 시작 자세를 관절값으로 저장하고, 각 에피소드 종료 후 별도 제어로 홈 자세에 복귀하는 조건에서 v2를 10회 평가했습니다.

- 전체 성공률: `4 / 10 = 40%`
- 평가 데이터: `lerobot_data/rollout_act_lens_cap_v2_home_mac`
- 홈 자세 설정: `config/lens_cap_home_pose.json`

홈 자세를 고정한 뒤 성공률은 기존 20%에서 40%로 상승했습니다. 다만 표본이 10회이므로, 이 결과만으로 데이터 보강 효과와 홈 자세 효과를 분리해 확정하지는 않습니다.

관찰된 실패 원인:

1. 뚜껑의 위치를 정확히 중심에 맞춰 집기보다, 보강 데이터에서 자주 나타난 접근 위치 중 하나로 향하는 양상이 보입니다. 넓은 무작위 위치를 50개 시연으로만 수집하면 위치별 예시가 부족해질 수 있습니다.
2. 그리퍼가 뚜껑을 밀어 위치가 바뀐 뒤에도 새 카메라 관측에 맞춰 재탐색·재접근하지 못하고, 원래 접근 동작을 계속하는 양상이 보입니다. 기존 데이터에는 이런 복구 상태에서 최종 성공으로 이어지는 시연이 없습니다.

#### 평가 중 키 조작

- `→`: 현재 에피소드를 즉시 끝내고 저장
- `←`: 현재 에피소드를 버리고 다시 기록
- `Esc`: 평가 세션 종료

`→`로 조기 종료한 에피소드는 부분 기록이므로 성공률 평가에서 제외하거나 삭제합니다.

부분 에피소드 삭제 예시:

```powershell
uv run lerobot-edit-dataset --repo_id=DY-01/rollout_act_lens_cap_v1 --root="<평가 데이터 폴더>" --new_repo_id=DY-01/rollout_act_lens_cap_v1 --new_root="<평가 데이터 폴더>" --operation.type=delete_episodes --operation.episode_indices="[9]" --push_to_hub=false
```

### 알려진 이슈와 대응

| 증상 | 원인 또는 상태 | 대응 |
|---|---|---|
| `OpenCVCamera(0) read failed` 또는 frame timeout | 허브 대역폭·전력 부족, 카메라 점유 또는 프레임 갱신 실패 | 카메라 앱을 종료하고 USB를 재연결합니다. 다른 USB 장치를 줄이거나 로봇과 카메라를 다른 포트/전원형 허브로 분리합니다. |
| `Record loop is running slower` | 로컬 CPU 추론이 목표 30Hz보다 느림 | 성능 평가에 기록하고, 향후 CUDA 가능 PC 또는 더 가벼운 실행 환경 검토 |
| `Relative goal position ... clamped` | 목표 관절 위치와 현재 위치 차이가 안전 제한보다 큼 | rollout에서는 `max_relative_target=5`를 유지합니다. 텔레오퍼레이션 수집에서는 리더·팔로워 시작 자세를 맞춘 뒤 `10`을 사용했습니다. |
| `Could not write TorqueEnable on id=5` | wrist_roll 모터 통신/토크 설정이 일시 실패 | 12V·USB를 재연결하고 기존 캘리브레이션 파일로 연결 점검 |
| 서보 기어 파손 | 팔로워 3번 모터의 내부 기어 손상 | STS3215-12V 교체, ID 3 설정 및 재캘리브레이션 완료 |

## Isaac Sim + Isaac Lab 향후 전환 후보

**현행 시뮬레이터는 MuJoCo입니다.** Windows와 Apple Silicon에서 실행할 수 있고, 그랩·놓기·카메라 감독·복구 상태 머신을 검증하는 데 충분하며, 이미 전체 데이터 생성·ACT 평가 파이프라인이 MuJoCo로 작동합니다.

Isaac Sim과 Isaac Lab은 당장의 다음 단계가 아니라 향후 전환 후보입니다. NVIDIA RTX 워크스테이션을 사용할 수 있고, 대규모 병렬 강화학습이나 고품질 시각 도메인 랜덤화가 실제 병목으로 확인될 때 전환을 검토합니다. 전환할 경우 Isaac Sim은 장면·물리·카메라 렌더링을, Isaac Lab은 병렬 환경의 데이터 생성과 정책 학습을 담당합니다.

현재 `simulation_assets/so101`에는 SO101의 MuJoCo(MJCF) 및 URDF 자산이 있습니다. Isaac 환경에는 이 로봇 자산을 USD/URDF 기반으로 가져오고, 상자·렌즈 뚜껑·책상·고정 RGB 카메라를 추가로 구성해야 합니다. 현재 자산은 그리퍼의 LeRobot 표현(`0=닫힘`, `100=열림`)과 동일한 제어 매핑이 아직 반영되지 않았으므로, 집기 학습 전에 이를 검증합니다.

### 시뮬레이션 데이터 생성 범위

1. 뚜껑을 화면 내 격자와 연속 좌표에 배치하고, 집기-운반-상자 투입까지 성공하는 궤적을 자동 생성합니다.
2. 뚜껑이 그리퍼에 밀려 좌·우·위·아래로 벗어난 상태를 의도적으로 만들고, 재탐색-재접근-재그립 후 성공하는 복구 궤적을 생성합니다.
3. 뚜껑·상자 위치, 크기, 마찰, 질량, 그리퍼 접촉, 책상 재질을 랜덤화합니다.
4. 조명, 그림자, 배경, 색상, 카메라 자세와 내부 파라미터, 이미지 노이즈를 랜덤화해 실제 웹캠과의 시각적 차이를 줄입니다.
5. 상태 기반 IK 또는 스크립트 전문가 정책으로 성공 궤적을 생성하고, 렌더링된 RGB 영상과 관절 행동을 LeRobot 호환 데이터셋 형태로 내보냅니다.

### 학습 및 실제 로봇 검증

1. 합성 데이터로 뚜껑 위치 인식과 복구 행동을 먼저 학습합니다.
2. 실제 로봇에서는 카메라 구도·물체 치수·그리퍼 접촉 차이를 보정하기 위한 소량의 고품질 시연만 수집합니다.
3. 합성 데이터와 실제 보정 데이터를 병합 또는 순차 미세 조정하고, 홈 자세 고정 조건에서 정식 10회 평가를 반복합니다.
4. 실제 실행에서는 `robot.max_relative_target=5`와 별도 홈 복귀 제어를 유지합니다.

### 실행 환경

현행 브랜치의 MuJoCo 개발·평가는 Windows에서 진행하고 있으며 Apple Silicon에서도 실행 가능합니다. ACT v2.2 산출물은 Mac에서 인계받았고, 추가 학습은 CUDA GPU 환경을 사용했습니다. 향후 Isaac Sim과 Isaac Lab으로 전환한다면 NVIDIA RTX GPU가 있는 Windows 또는 Linux 워크스테이션·서버가 필요합니다.

- [Isaac Lab 시각 도메인 랜덤화 가이드](https://docs.nvidia.com/learning/physical-ai/getting-started-with-isaac-lab/latest/transferring-robot-learning-policies-from-simulation-to-reality/03-bridging-the-gap-simulation-enhancement/01-visual-domain-randomization.html)

9. MuJoCo에서 데이터 생성량이나 시각 도메인 랜덤화가 병목이 될 때 Isaac Sim·Isaac Lab 전환을 재검토합니다.

## GitHub 아티팩트 관리

재현에 필요한 학습 데이터와 ACT 체크포인트는 [`artifacts/`](./artifacts)에 선별해
Git LFS로 관리합니다. `*.safetensors`, `*.mp4`, `*.parquet` 등 대용량 파일은
`.gitattributes`의 LFS 규칙을 따르며, 설정 JSON과 메타데이터는 일반 Git에 저장합니다.

다음 항목은 계속 `.gitignore`로 제외합니다.

- `.venv/`와 Python 캐시
- 실행 중 계속 덮어쓰는 `outputs/`
- 정리되지 않은 로컬 `models/`, `lerobot_data/`, 임시 영상
- Hugging Face 토큰, API 키, `.env`, 기타 비밀 정보

업로드할 때는 `outputs/` 전체를 그대로 커밋하지 않고, 재현에 필요한 최종 데이터셋과
체크포인트만 `artifacts/`로 복사해 검수 후 커밋합니다. 이렇게 하면 코드 저장소의
구조를 유지하면서 GitHub clone/pull만으로 필요한 실험 자산도 받을 수 있습니다.
